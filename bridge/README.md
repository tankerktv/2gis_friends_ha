# `bridge/` — первый подход к задаче

**Это не часть интеграции и не запускается в Home Assistant.** Самостоятельная
служба, написанная до неё. Оставлена сознательно; ниже — зачем.

## Что это

Отдельный процесс, который делает то же самое, но другим путём:

```
zond WS  ->  нормализация  ->  MQTT Discovery  ->  Home Assistant
```

Home Assistant узнаёт о друзьях через MQTT: мост публикует на каждого
устройство с тремя сущностями, HA подхватывает их автоматически.

| Файл | Назначение |
|---|---|
| `main.py` | точка входа, склейка и обработка сигналов |
| `zond.py` | WS-клиент с keepalive и переподключением |
| `models.py` | разбор фреймов в нормализованные позиции |
| `mqtt_pub.py` | публикация и MQTT Discovery |
| `tokens.py` | получение и обновление токена, три провайдера |
| `config.py` | настройки из переменных окружения (см. `.env.example`) |

## Почему в итоге сделана интеграция

Мост работает, но требует от пользователя трёх вещей: поднять ещё один
процесс, иметь брокер MQTT и разобраться с переменными окружения. Нативная
интеграция ставится из HACS в несколько кликов, настраивается в интерфейсе
и переживает перезапуски Home Assistant без посторонней помощи.

Поэтому дальше развивается `custom_components/twogis_friends/`, а мост
остался в том виде, в каком работал.

## Почему не удалён

**Здесь есть то, чего в интеграции пока нет.** `tokens.py` умеет получать и
обновлять токен сам, тремя способами. Интеграция сейчас берёт готовый токен,
который пользователь добывает руками. Когда дойдут руки до автологина, брать
логику будем отсюда.

**Это независимая проверка разбора протокола.** Два парсера, написанных по
одним и тем же наблюдениям, но порознь. Если 2ГИС что-то поменяет, сравнение
поведения помогает понять, что именно.

**Он пригодится тем, кому не нужен Home Assistant.** MQTT читает что угодно.

## Состояние

Работает, но не развивается. Тестами **не покрыт** — они написаны для
интеграции. Если решите пользоваться мостом всерьёз, начните с тестов:
`models.py` здесь такой же удобный для проверки, как и в интеграции.

Настройка — через переменные окружения, шаблон в `.env.example` в корне
репозитория. Запуск:

```bash
python -m bridge.main
```
