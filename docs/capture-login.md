# Снятие флоу логина 2ГИС

Цель — узнать, каким запросом выдаётся `access_token`, чтобы интеграция могла
логинить сама, без браузера внутри Home Assistant.

Тем же способом уже разобран протокол друзей (см. [findings.md](findings.md)),
так что метод рабочий.

---

## Почему это важнее, чем headless-браузер

Пока неизвестно **две вещи**, и от них зависит вся архитектура:

1. **Где страница берёт токен.** В HTML его нет (проверено: документ на 737 КБ,
   ни `token`, ни `__customcfg`), ни в одном теле ответа — тоже. Значит либо
   клиентское хранилище, либо запрос, который не попал в запись.
2. **Чем логинится аккаунт.** В `users/me` видны identities `google`, `sberid`,
   `apple`. Если вход только через них — автоматизировать нечего: это чужие
   OAuth-провайдеры с 2FA и антиботом. Если есть телефон+SMS — код всё равно
   вводит человек, браузер тут не помогает.

Отдельно есть **`POST https://2gis.ru/_/auth/refresh`** — вызывается при загрузке
страницы, тело пустое, ответ `{"code":200,"status":"success"}`. Он продлевает
сессию. Если окажется, что токен добывается из сессии одним запросом, то связка
«хранить куки + дёргать refresh» даёт бессрочную работу вообще без логина.

**Это и есть цель разведки.**

---

## Что снимать

Нужны два сценария. Первый быстрый и, возможно, достаточный.

### Сценарий 1: откуда берётся токен в уже залогиненной сессии (2 минуты)

1. Открой https://2gis.ru/tomsk, F12 → вкладка **Application**.
2. Слева: **Local Storage** → `https://2gis.ru`. Дальше **Session Storage** → то же.
3. В поле фильтра вбей первые 8 символов токена (из URL сокета).
4. Запиши: **в каком хранилище и под каким ключом** он лежит.
   Если ключ есть — скопируй **имя ключа и форму значения** (сам токен замени
   на `<TOKEN40>`): это может быть голая строка, а может JSON с `expires_at`.
5. Загляни ещё в **Cookies** → `https://2gis.ru`: выпиши **имена** кук
   (значения не нужны) — по ним будет понятно, что хранит сессию.

Если токен нашёлся в localStorage с полем срока — половина ответа уже есть.

### Сценарий 2: сам логин (5 минут)

Нужен, только если из сценария 1 не видно, кто токен кладёт.

1. **Приватное окно** (чтобы не потерять текущую сессию).
2. F12 **до** перехода, вкладка Network, галка **Preserve log**, фильтр `Fetch/XHR`.
3. Зайти на https://2gis.ru → войти в аккаунт **своим обычным способом**.
4. После успешного входа — в поле поиска Network вбей первые 8 символов
   нового токена. Network ищет и по телам ответов.
5. Найденный запрос — тот самый эмитент. Снять:
   - метод и URL;
   - тело запроса (пароль/код **вырезать**);
   - **тело ответа** — есть ли рядом `expires_in`, `refresh_token`, `token_type`;
   - какие куки при этом выставились (`Set-Cookie`, только имена).
6. Сохранить всё как HAR: правый клик в Network → **Save all as HAR**.

> HAR логина содержит боевые учётные данные. Прогони через
> `python tools/scrub.py login.har -o login-clean.har` перед отправкой,
> а лучше выпиши руками только пункты выше.

## Что будет дальше по результату

| Что выяснится | Как это реализуется в HA |
|---|---|
| Токен выдаётся same-origin запросом по куке | Хранить куки + `/_/auth/refresh` → полностью автоматически, без логина и браузера |
| Есть эндпоинт логина по телефону + SMS | Многошаговый config flow: телефон → код → токен. Код вводится в HA один раз |
| Есть логин по email + паролю | Config flow в один шаг, полностью автоматический |
| Вход только через Google/Apple/SberID | Автоматизировать нельзя. Остаётся разовая вставка токена + реавторизация |

Первые три варианта — это **нативная интеграция без единого мегабайта Chromium**.
Четвёртый — единственный, где headless в принципе оправдан, и то он не избавит
от участия человека, а только перенесёт его.
