# Снятие данных из DevTools: zond.api.2gis.ru

Цель — получить два куска: **(A)** как авторизуется WebSocket, **(B)** структура входящего
фрейма с координатами. Плюс проверить `GET /sharing/sessions`.

---

## 0. Подготовка (важно — иначе потеряешь handshake)

1. Chrome/Edge, залогинься на https://2gis.ru/tomsk обычным способом.
2. Открой **F12 → Network** и включи `Preserve log`.
3. **Только теперь** переходи на `/tomsk/friendsList` (или жми F5 на ней).

> WS-соединение записывается только если DevTools был открыт **до** его установки.
> Сообщения (`Messages`) буферизуются только пока панель открыта — закроешь, потеряешь.

## A. Авторизация сокета

### A.1 Сузим пространство поиска заранее

Браузерный `WebSocket` API **физически не умеет** ставить произвольные заголовки
(нет `Authorization:`). Значит токен попадает на сервер ровно одним из четырёх способов:

| Способ | Где искать в DevTools | Вероятность |
|---|---|---|
| query-параметр URL | `Headers → Request URL` | высокая |
| `Sec-WebSocket-Protocol` (subprotocol) | `Headers → Request Headers` | высокая |
| cookie (cross-site, нужен `SameSite=None`) | `Headers → Request Headers → Cookie` | средняя |
| первый исходящий фрейм после `open` | `Messages`, первая зелёная ↑ строка | высокая |

Часто комбинация: сокет открывается анонимно, а первый ↑ фрейм — это `auth`/`login` с токеном.

### A.2 Что нажимать

1. В Network кликни кнопку фильтра **`WS`** (рядом с `Fetch/XHR`, `JS`, `Img`).
2. Появится строка вида `1.1` с доменом `zond.api.2gis.ru`. Кликни по ней.
3. Вкладка **Headers** — снять полностью:
   - `General → Request URL` — **весь URL с query-строкой**
   - `Response Headers → Sec-WebSocket-Protocol` (что сервер выбрал из предложенного)
   - `Request Headers`:
     - `Sec-WebSocket-Protocol` — список предложенных подпротоколов
     - `Sec-WebSocket-Key`, `Sec-WebSocket-Version` — не нужны, но пусть будут
     - `Origin` — нужен, скорее всего сервер его валидирует
     - `Cookie` — **не присылай значения**, пришли только **имена** кук
       (`Ctrl+F` в списке → интересуют имена вида `*sid*`, `*auth*`, `*token*`)

> Если вместо заголовков видишь «Provisional headers are shown» — перезагрузи страницу
> с открытым DevTools, это значит запрос не был перехвачен целиком.

### A.3 Первые исходящие фреймы

Вкладка **Messages** (в старых сборках — `Frames`):

- ↑ зелёные — от клиента, ↓ белые/серые — от сервера.
- **Сними первые 3 исходящих (↑) фрейма и первый входящий (↓) после них.** Это handshake:
  auth → ack → subscribe.
- Правый клик по строке → **Copy message**.

### A.4 Ещё до анализа — распознай транспорт

Посмотри на самый первый фрейм. Если он выглядит как:

| Что видишь | Это | Последствие |
|---|---|---|
| `{"type":"...","payload":{...}}` | сырой JSON | идеально, трек Б прямой |
| `0{"sid":"...","pingInterval":25000}`, потом `40`, `42["ev",{...}]` | **socket.io / engine.io** | нужен `python-socketio`, у него свой ping (`2`↔`3`) |
| `o`, `a["..."]`, `h` | **SockJS** | свой протокол-обёртка |
| `CONNECT\naccept-version:1.2\n\n\x00` | **STOMP** | свой фрейминг |
| `Binary Message`, `(N) bytes`, кракозябры | **protobuf / MessagePack / CBOR** | нужен дамп байтов в hex, схема не гарантирована |

**Если фреймы бинарные — напиши сразу, это меняет план.** Для дампа:
правый клик → `Copy message` даст текстовое представление; дополнительно
скопируй из `Console` результат перехвата (см. A.5).

### A.5 Запасной вариант: перехват через Console

Если Messages неудобно копировать (много фреймов, длинные строки) — до загрузки
страницы вставь в **Console** патч и перезагрузи:

```js
// вставить в Console, затем F5 (Preserve log должен быть включён)
(() => {
  const OW = window.WebSocket;
  window.__wsLog = [];
  window.WebSocket = function (url, protocols) {
    const ws = new OW(url, protocols);
    window.__wsLog.push({ t: Date.now(), dir: 'open', url: String(url), protocols });
    const os = ws.send.bind(ws);
    ws.send = (d) => { window.__wsLog.push({ t: Date.now(), dir: 'out', d: String(d).slice(0, 4000) }); return os(d); };
    ws.addEventListener('message', (e) => {
      const d = typeof e.data === 'string' ? e.data.slice(0, 8000) : `[binary ${e.data.size ?? e.data.byteLength}b]`;
      window.__wsLog.push({ t: Date.now(), dir: 'in', d });
    });
    ws.addEventListener('close', (e) => window.__wsLog.push({ t: Date.now(), dir: 'close', code: e.code, reason: e.reason }));
    return ws;
  };
  window.WebSocket.prototype = OW.prototype;
  console.log('WS hook installed');
})();
```

Потом: `copy(JSON.stringify(window.__wsLog, null, 2))` — попадёт в буфер обмена.
Это же даст **точные тайминги** — из них видно интервал keepalive.

## B. Структура фрейма с координатами

1. Побудь на странице **6+ минут** — нужно поймать:
   - **snapshot** — первый большой ↓ фрейм со списком всех друзей;
   - **update** — инкрементальный фрейм при движении друга (структура часто *другая*);
   - **keepalive** — что клиент шлёт, чтобы сокет не умер по `friendsSocketIdleTimeout: 300000`.
     Смотри на ↑ фреймы, повторяющиеся с ровным периодом (обычно 25–60 с).
2. Если друзья стоят на месте — попроси кого-нибудь пройтись, иначе update-фрейма не будет.
3. Если сокет всё же отвалился — во вкладке `Messages` последней строкой будет close;
   зафиксируй **код закрытия** (1000 / 1006 / 4001 / 4401 — коды 4xxx обычно означают auth-ошибку).

### Минимальный чек-лист «что прислать»

- [ ] полный Request URL сокета (с query)
- [ ] `Sec-WebSocket-Protocol` request + response
- [ ] имена (не значения!) кук, ушедших на `zond.api.2gis.ru`
- [ ] первые 3 ↑ фрейма и первый ↓ после них
- [ ] snapshot-фрейм с координатами
- [ ] update-фрейм с координатами (если отличается)
- [ ] пара keepalive ↑/↓ фреймов + интервал между ними
- [ ] код закрытия, если сокет упал
- [ ] `GET /sharing/sessions` — статус, request headers (имена), тело ответа

## C. `GET https://zond.api.2gis.ru/api/1.1/sharing/sessions`

1. Фильтр `Fetch/XHR`, в поле поиска — `sharing`.
2. Если запроса нет вообще — веб им не пользуется, но эндпоинт всё равно проверяем вручную (см. ниже).
3. Если есть — правый клик → **Copy → Copy as cURL (bash)**. Это даст сразу всё:
   метод, заголовки, куки, токен.
   **Этот cURL содержит секреты целиком — обязательно прогони через `tools/scrub.py`
   перед отправкой мне.**
4. Обрати внимание в `Request Headers` на:
   - `Authorization: Bearer <...>` — есть или нет
   - кастомные `X-*` заголовки (2ГИС любит `X-App-*`, `X-Device-*`)
   - `Cookie` — уходит ли она на `zond.` (cross-origin относительно `2gis.ru`)

Если запроса в списке нет — проверим вручную:

```bash
python track_a/probe_sessions.py --token "<JWE>" --cookie-file cookies.txt
```

## D. Обезличивание — что резать, что НЕ трогать

### Резать

| Что | Чем заменить |
|---|---|
| JWE-токен (5 сегментов через `.`) | `<JWE:5segs:len=1234>` |
| JWT (3 сегмента) | `<JWT:3segs:len=812>` |
| значения кук | `<COOKIE:имя>` |
| user_id / friend_id | `FRIEND_1`, `FRIEND_2` — **консистентно** по всему дампу |
| имена, телефоны, аватарки | `PERSON_1`, `+7XXXXXXXXXX` |
| координаты | округлить до 2 знаков (**сохранив тип**: `56.48` если было float, `"56.48"` если строка) |

### НЕ трогать (иначе дамп бесполезен)

- имена ключей и вложенность
- **типы** значений: `55.7558` vs `"55.7558"` — принципиально разные вещи
- формат timestamp: `1753500000` / `1753500000000` / `"2026-07-26T10:00:00Z"` — нужен как есть
- коды/строки событий (`"type"`, `"event"`, `"op"`, `"cmd"`)
- battery: `87` vs `0.87` vs `"87%"` — оставь как есть, это не приватное

### Безопасно и полезно прислать: header JWE-токена

Первый сегмент до точки — это **не секрет**, просто base64url-JSON с алгоритмом:

```js
// в Console
JSON.parse(atob('<токен>'.split('.')[0].replace(/-/g,'+').replace(/_/g,'/')))
// → {"alg":"RSA-OAEP-256","enc":"A256GCM","kid":"...","cty":"JWT"}
```

Пришли этот объект — по `kid`/`cty` понятно, надо ли вообще пытаться его читать
(при `RSA-OAEP-256` содержимое нам недоступно, токен для нас — непрозрачная строка,
и это нормально: мы его просто пробрасываем).

### Скрипт

```bash
# из файла
python tools/scrub.py raw_capture.txt -o clean_capture.txt

# из буфера обмена в буфер обмена (PowerShell)
Get-Clipboard | python tools/scrub.py - | Set-Clipboard
```

Скрипт держит `scrub-map.json` — один и тот же id всегда получит один и тот же алиас,
даже если гонишь несколько файлов по очереди.
